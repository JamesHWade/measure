This is guidance for #81/#107, not a parser or an mzML capability claim. The cited issue text and earlier service notes were used only as pointers. MoSeS SI claims are not repeated: the issue's SI URL was not available for verification, and no MoSeS source semantics below depend on it.

## Minimum scan record

Model a run/injection as an ordered collection of scan records, each linked to its source and retaining a native scan identifier or acquisition ordinal. A scan carries its own scan start time (with unit), MS level, polarity, representation (centroid/profile), and ragged m/z and intensity vectors. Keep each scan's coordinates as supplied; do not force scans onto a shared or regular m/z grid. PSI-MS defines scan number as an acquisition-order ordinal, scan start time relative to run start, MS level as the stage reached, and separate positive/negative polarity terms. It separately defines centroid data as discrete peak points and profile data as a signal distribution over the coordinate range ([PSI-MS CV terms](https://github.com/HUPO-PSI/psi-ms-CV/blob/master/psi-ms.obo#L1139-L1167), [scan/MS-level terms](https://github.com/HUPO-PSI/psi-ms-CV/blob/master/psi-ms.obo#L348-L357), [scan number](https://github.com/HUPO-PSI/psi-ms-CV/blob/master/psi-ms.obo#L21253-L21259), [MS level](https://github.com/HUPO-PSI/psi-ms-CV/blob/master/psi-ms.obo#L3908-L3913)).

This matches Spectra's per-spectrum metadata plus per-spectrum peak data: each spectrum has one set of variables, while m/z and intensity are vectors that can vary in length by scan. An empty spectrum remains a spectrum record with zero peak rows. Spectra distinguishes file-relative `scanIndex` from `acquisitionNum`, so retain source identity and do not treat retention time alone as a unique scan key ([Spectra 1.22.2 manual, pp. 66–69, 76, 113–116](https://bioconductor.org/packages/3.23/bioc/manuals/Spectra/man/Spectra.pdf)).

Keep these states separate:

- **Acquired-empty:** the scan record exists and its peak arrays have length zero. Keep the scan metadata and empty arrays.
- **Missing/unavailable:** an expected scan or field has no recorded value. Do not synthesize an empty scan or zero intensity. A gap in an imported sequence alone does not prove which event occurred; retain a missing/unknown status unless source evidence establishes it.
- **Unknown/unreported metadata:** retain as unknown (typed missing value), not an inferred default such as MS1, positive polarity, profile mode, or unsaturated. Spectra's core variables return typed missing values when not defined, and its `centroided` accessor permits `NA` for undefined mode.
- **Declared saturation:** retain the source-reported numeric reading and a separate saturation/censoring status, including any reported threshold or affected interval. Do not turn it into zero, treat it as an exact unsaturated value, or infer saturation from a high numeric value alone. This slice stores saturation as an explicit local declaration and assigns no PSI accession; keep any original vendor/source field separate from that local mask.

The last two are data-quality states, not substitute numerical values. Keep acquisition status at scan level and missing/saturation masks at the narrowest source-supported point or interval level.

## Bounded TIC and XIC

A chromatogram is a derived time series keyed back to the contributing scan records. Preserve scan order, scan IDs, source timestamps, and repeated timestamps. Make the selection scope explicit: run/injection, MS level, polarity, optional m/z window, and time/scan bounds. PSI-MS distinguishes MS1 and MS2 TIC series, supporting separate level-scoped series rather than silently combining precursor and product scans ([MS1 TIC](https://github.com/HUPO-PSI/psi-ms-CV/blob/master/psi-ms.obo#L29692-L29704), [MS2 TIC](https://github.com/HUPO-PSI/psi-ms-CV/blob/master/psi-ms.obo#L29706-L29717)). Do not interpolate, resample, or sum mixed-polarity/level scans by default.

Preserve **source-reported TIC** separately from **derived TIC** and state the derivation. PSI-MS defines a TIC chromatogram as total ion current detected in each spectrum versus time; it defines selected ion current chromatograms as a specific ion current versus time ([TIC](https://github.com/HUPO-PSI/psi-ms-CV/blob/master/psi-ms.obo#L1942-L1947), [selected-ion current](https://github.com/HUPO-PSI/psi-ms-CV/blob/master/psi-ms.obo#L4766-L4771)). Spectra likewise exposes the initially reported TIC separately from recalculation: `tic(initial = FALSE)` is the recalculated sum (`ionCount`). `ionCount` sums a spectrum's intensities; it is a defined software calculation, not proof of grid-independent physical integration ([Spectra 1.22.2 manual, pp. 66–68, 112–116](https://bioconductor.org/packages/3.23/bioc/manuals/Spectra/man/Spectra.pdf)).

For centroid data, a declared sum over selected discrete peaks is a bounded, reproducible TIC/XIC calculation, with the intensity units and selection rule retained. For profile data, plain `sum(intensity)` adds sampled signal values without m/z spacing weights. If the same signal is sampled twice as densely, that sum can roughly double; it is not the area integral. A profile-derived signal area needs an explicit method using the actual m/z coordinates and requested bounds (for example, a stated quadrature rule), or an explicitly declared peak-picking transformation. If source metadata says each value already represents a bin amount, preserve and follow that source convention. Do not label an unweighted profile-point sum as physical integration.

An XIC calculation must record target m/z and tolerance/window (absolute or ppm), polarity, MS level, and extraction rule (e.g. centroid peak sum, profile peak-pick, or coordinate-weighted profile integral). Apply it to each scan's native coordinates. The CV's selected-ion term does not specify a local extraction tolerance, so that parameter belongs to the derived result's provenance. Keep a chromatogram's per-scan intensity distinct from area under the chromatogram: PSI-MS has separate area-under-TIC terms ([MS1 area](https://github.com/HUPO-PSI/psi-ms-CV/blob/master/psi-ms.obo#L27770-L27776), [general area under TIC](https://github.com/HUPO-PSI/psi-ms-CV/blob/master/psi-ms.obo#L28963-L28972)).

For empty scans, retain emptiness independently of TIC value. The Spectra manual documents `ionCount()` returning `NA_real_` for an empty scan, but its `tic()` descriptions differ on empty results (`NA_real_` in the backend method section and `0` in the `Spectra` accessor section); it also distinguishes source-reported TIC from recalculation. This is a reason to specify the core derived-empty rule and preserve any source-reported TIC unchanged ([Spectra manual, pp. 66, 76, 112–116](https://bioconductor.org/packages/3.23/bioc/manuals/Spectra/man/Spectra.pdf)).
